3. มาตรการดูแลรักษาให้ความเสี่ยงต่ำต่อไป

โดเมนกลุ่มนี้อยู่ในสถานะที่ดีในปัจจุบัน แต่ช่องโหว่ที่เหลือส่วนใหญ่เป็นรายการ configuration ที่พบซ้ำๆ (header ที่ขาดไป, cookie flag, ความปลอดภัยของสคริปต์จากภายนอก) มากกว่าช่องโหว่เร่งด่วน มาตรการด้านล่างช่วยให้กลุ่มนี้ ยังคงมีความเสี่ยงต่ำต่อไป

ลำดับมาตรการคำอธิบายเพิ่มเติม
1อัปเดตซอฟต์แวร์อย่างสม่ำเสมอแม้เป็นโดเมนที่มีความเสี่ยงต่ำ ก็ควรแพตช์ OS, web server, PHP/CMS และ JS library ตามรอบปกติ เพื่อไม่ให้เลื่อนเข้าสู่สถานะ End-of-Life โดยไม่รู้ตัว
2ตั้งค่า Security Header มาตรฐานติดตั้ง CSP, HSTS, X-Frame-Options และ SRI ให้ครบทุกโดเมน เพราะช่องโหว่ระดับ Medium/Low ส่วนใหญ่ในกลุ่มนี้มาจาก header ที่ขาดไป ไม่ใช่ช่องโหว่ในโค้ด
3ปรับปรุงการตั้งค่า Cookieกำหนด Secure, HttpOnly, SameSite และ Max-Age ที่เหมาะสมให้ทุก cookie เพื่อปิดช่องโหว่ระดับ Low ที่พบซ้ำๆ ในกลุ่มนี้
4ตรวจสอบสคริปต์จากบุคคลที่สามเพิ่ม Subresource Integrity (SRI) ให้กับสคริปต์ที่โหลดจากภายนอก (ปุ่มแชร์, CDN) ที่หลายโดเมนในกลุ่มนี้อ้างอิงอยู่
5ติดตามการต่ออายุ SSL Certificateหลายโดเมนใช้ wildcard certificate ของ *.kku.ac.th ร่วมกัน ควร monitor วันหมดอายุจากส่วนกลาง เพื่อไม่ให้หมดอายุพร้อมกันหลายเว็บ
6สแกนซ้ำเป็นระยะแม้กลุ่มนี้ไม่มี Critical/High ในตอนนี้ ควรสแกนซ้ำตามรอบ เพราะ CVE ใหม่อาจทำให้เวอร์ชันที่ยังซัพพอร์ตอยู่กลายเป็นความเสี่ยงในอนาคต
